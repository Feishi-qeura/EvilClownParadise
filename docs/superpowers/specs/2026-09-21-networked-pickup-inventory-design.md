# 联网拾取、装备与局内背包设计

## 目标

在现有 `AECPPickupItem`、`AECPPlayerBase` 和 `AECPPlayerController` 拾取链上增加服务器权威的检查拾取、装备、局内入库和死亡爆出流程。Listen Server 与远端客户端都能发起拾取；多人竞争在服务器同帧内优先主机，其次按服务器分配的加入序号，跨帧请求先到先得。

本阶段背包是无限容量、无 UI、无跨局持久化的局内临时背包。测试阶段把玩家进入布娃娃视作死亡掉落触发；正式死亡仍通过 `OnDied` 触发同一条掉落路径。

## 状态模型

物品使用明确枚举表示生命周期：

- `World`：地面自由物体，开启碰撞、物理和移动复制，可以被瞄准和申请拾取。
- `Pickup`：检查拾取态，归属一名玩家并附到其相机前。拥有者显示鼠标、锁定移动和镜头，按住左键拖动旋转物品。
- `Equipped`：装备态，附到玩家现有 `HitScanSocket2`，玩家恢复正常移动和镜头。
- `Stored`：库入态，归属玩家但隐藏、关闭碰撞和物理，并进入网络休眠。

允许的状态转换为：

- `World -> Pickup`：玩家按 `F`，服务器重新射线验证并赢得竞争。
- `Pickup -> World`：右键放下，或持有者失效。
- `Pickup -> Equipped`：按 `2`。
- `Pickup -> Stored`：按 `V`。
- `Equipped -> World`：按 `G` 投掷，或持有者失效。
- `Equipped -> Stored`：按 `V`。
- `Stored -> World`：测试布娃娃、正式死亡、断线或角色销毁时爆出。

非法跨状态请求保持原状态，不执行部分切换。

## 联网与竞争裁决

客户端输入只发送意图，不提交可信目标、射线、投掷方向、力量或最终旋转。服务器重新检查角色存活、运动锁、当前状态、距离、遮挡、目标类型、物品归属、组件和插槽。

合法 `F` 请求进入目标物品的本服务器帧请求队列，并在下一服务器帧开始时结算。此方式不增加固定毫秒等待，只提供同帧确定性：

1. Listen Server 本地主机最高优先级。
2. 其他请求按 `AECPGameMode::PostLogin` 分配的单调加入序号排序。
3. 跨服务器帧的请求由先完成结算者取得物品；已成功的物品不可被主机或后续请求强抢。

瞄准焦点只负责高亮，不再授予占用权，也不能阻止另一名玩家提交拾取请求。

## 输入与表现

现有 `F` 继续使用 Enhanced Input。需求固定的 `2`、`G`、`V`、鼠标左键和右键直接在 `AECPPlayerController` 绑定，避免强制改写当前已有且未提交的 InputAction/Mapping 资产。

进入 `Pickup` 后，拥有者客户端显示鼠标并进入允许游戏接收鼠标按键的输入模式。角色输入和镜头输入被拒绝，服务器同步禁用角色移动，防止修改客户端绕过本地锁。物品附到相机并使用可配置检查偏移。

左键拖动采用本地预测保证即时手感，并以限频、不可靠 RPC 上传旋转增量。服务器验证物品归属和状态、限制单次角度，再复制权威旋转。退出 `Pickup`、失去控制权或结束游戏时必须恢复鼠标、输入模式和移动。

进入 `Equipped` 后，物品附到现有携带网格的 `HitScanSocket2`，玩家正常移动和观察。按 `G` 时服务器使用自己的玩家视角施加 `ThrowStrength` 冲量。物理引擎根据质量自动产生“质量越大、速度变化越小”的效果，不再手动除以质量，避免形成质量平方反比。

## 背包与掉落

玩家在服务器维护库入物品引用集合；物品自身的复制状态保存所属玩家，因此角色引用只用于枚举和批量爆出。入库不销毁 Actor，从而保留实例旋转、未来耐久和自定义数据。

库入时物品隐藏、关闭物理和碰撞、停止移动复制并进入休眠。爆出前唤醒网络，清除归属，在尸体或角色位置周围按可配置半径分散放置，恢复碰撞、物理、移动复制并强制网络更新。当前检查物品和装备物品也通过同一清理入口落地。

测试期间，服务器检测玩家从非布娃娃进入布娃娃的边沿并触发一次爆出；退出再进入可再次触发。正式死亡的 `OnDied` 调用相同函数，函数自身幂等，避免死亡与布娃娃在同帧重复释放。

## 文件边界

- `ECPPickupTypes`：状态枚举、请求优先级值与纯规则函数。
- `ECPPickupItem`：权威状态、同帧请求队列、附着/隐藏/物理表现、旋转和投掷。
- `ECPPlayerBase`：服务器射线验证、当前检查/装备引用、库存集合、请求 RPC、移动锁和批量爆出。
- `ECPPlayerController`：加入优先级、固定按键、鼠标拖动采样和本地输入模式。
- `ECPGameMode`：在 `PostLogin` 为控制器分配稳定的服务器加入序号。
- `ECPPickupTypesTests`：状态转换、竞争排序和投掷质量行为的自动化测试。

所有新增复杂逻辑、网络分支、空值保护、API 调用和状态切换前写原因/意图注释。不会覆盖当前工作区已有的蓝图、地图、配置或 RiderLink 修改。

## 故障恢复

- 相机、物理根组件或装备插槽缺失时拒绝转换并记录明确日志，原状态不变。
- 角色断线、销毁、死亡或进入测试布娃娃时，服务器释放其全部物品。
- 复制状态包含递增版本号；旧 RepNotify、附着复制或移动复制回调不能覆盖更新状态。
- 暂未映射到客户端的持有者引用会触发短间隔重试，但先关闭错误物理，避免物品在等待引用时掉落。
- 库存中的无效弱引用会在访问和爆出时清理。

## 验证

自动化验证包括合法状态转换、非法转换拒绝、主机/加入序号排序，以及固定冲量下重物速度变化更小的规则。随后编译 Editor 目标，并进行 Listen Server 加两客户端 PIE 验证：客户端拾取、拖动旋转、装备、投掷、入库、布娃娃爆出、断线清理、同帧竞争和跨帧先到先得。
