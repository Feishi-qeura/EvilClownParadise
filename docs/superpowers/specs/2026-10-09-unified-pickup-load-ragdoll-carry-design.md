# 统一物品、物理拾取、负重与布娃娃搬运设计

日期：2026-10-09。状态：用户已批准开始实施；玩法已实现，验证结果及实施修订见 `docs/carry-load-validation.md`。

## 目标与已确认规则

在当前 UE 5.8 工程中解决手持中型物体穿模，让小、中型物体共享类特性和代码，按角色拥有的物品总重量降低移动与跳跃能力，并允许队友拾取、搬运布娃娃角色。实现遵循现有 GameFeature 单向依赖和服务器权威模型。

用户已确认的设计方向：

- 公共物品类承担重量、状态、碰撞与跟随；小、中型差异通过配置表达，旧中型类保留兼容壳。
- 手持物通过服务器物理抓取保留场景碰撞，客户端显示服务器结果。
- 背包、手持、装备去重计重。角色最大承重默认 200 kg，可公开配置、运行时扩展。
- 行走、跑步、蹲行速度和跳跃初速度按线性负重倍率衰减；达到上限时不能主动移动或起跳，但可以卸重。
- 普通物品检查态保留当前分支实际的可移动输入行为并受负重限制；搬运队友允许行走。原设计对检查态移动锁的判断来自旧文档，实施时已核对并修正。
- 被搬运的布娃娃不能起身；放下后恢复现有起身检查。
- 保留现有进入布娃娃时掉出全部物品的规则。

本规格补充可实施边界：角色身体重量默认 80 kg、可配置；队友只能搬运和放下，不能入库、装备或投掷；同一搬运者只能持有一个活跃目标。背包不因超重拒绝入库，200 kg 是运动阈值而非容量阈值。

## 当前代码证据

- `ECPPickupItem.cpp::ApplyAttachmentState` 对所有非 World 状态关闭物理和碰撞，并停止移动复制；Pickup 随后附着相机。
- `ECPMediumPickupItem.cpp` 捕获并复制 50～120 kg 的质量，以无 Sweep 的 `SetActorTransform` 平滑跟随。碰撞关闭和直接变换共同造成手持穿模。
- `AECPPickupItem` 已实现 World / Pickup / Equipped / Stored 状态、竞争仲裁、焦点、旋转序号和释放恢复。中型子类已有复用关系，但质量和跟随逻辑仍仅存在于子类。
- `AECPPlayerBase` 的服务器槽位为检查、装备与库存，客户端仅收到库存数量；目前没有总重量字段或负重运动计算。
- `AECPCharBase::OnRep_Running`、移动锁恢复和布娃娃恢复会更新运动参数，负重必须进入同一刷新路径，避免跑步或起身覆盖减速。
- 现有布娃娃仅在服务器模拟完整骨骼物理，客户端消费姿态快照。玩家在布娃娃进入边沿执行 `DropAllOwnedPickups`。
- 阵营已有 Foundation 的 `ECPTeam` 常量和 Character 的 `GetCharacterTeamId` 契约。

## 方案选择与功能边界

采用“公共物品基类＋配置＋旧类兼容壳”。直接删除旧中型类会迫使蓝图和关卡迁移；全量组件化会扩大本次范围。公共搬运契约仅用于连接物品与角色，不重写既有库存协议。

| 模块 | 职责 | 依赖边界 |
| --- | --- | --- |
| ECPFoundation | 公共可搬运目标契约：物理组件、骨骼、质量、可用性、持有者及权威开始/结束通知 | 不引用具体角色、物品或 GameFeature 类型 |
| ECPCharacter | 身体重量、复制的负重属性、运动参数刷新、布娃娃搬运状态与恢复限制 | 只依赖 Foundation 和已有引擎模块 |
| ECPInteraction | 公共物品实现、服务器物理抓取、输入、目标扫描、仲裁、库存计重与卸重 | 依赖 Character、Foundation；Character 不反向依赖 Interaction |

功能依赖在 `.uplugin` 与 Build.cs 保持一致，不新增宿主模块依赖、循环依赖或第二个启动入口。玩法资源继续归属 `Content/Project/Interaction` 和 `Content/Project/Character`。本次不改 BMMC、历史 redirector 或无关未提交资源。

## 公共物品实现及兼容

`AECPPickupItem` 统一提供权威质量查询、质量捕获、物理抓取参数、装备/存储能力及现有生命周期。质量来自实际模拟根组件；物理体尚未可用时优先采用实例质量覆盖，再采用可配置默认重量，拒绝非有限或负值。

质量在进入 World、拾取前和合法运行时质量变更后由服务器确认并复制；入库后仍保留确认质量，不能因物理关闭而变成零。物品改变质量时通知当前持有者刷新负重。

公共类配置至少包含默认质量、质量约束、装备与入库能力、跟随响应和物理抓取参数。小物品默认保留装备和入库能力；中型兼容类默认保留 80 kg、50～120 kg 范围、禁止装备和入库以及较慢跟随参数。设计人员可在物品配置中扩展能力。

`AECPMediumPickupItem` 保留现有反射类型与已序列化配置属性，迁移为默认配置适配层；不再保留独立质量采集、复制或跟随算法。蓝图可用的既有函数继续可调用。修改属性归属时核对旧包序列化与引用，不直接改写 `.uasset` 二进制。

现有物品 World / Pickup / Equipped / Stored 状态和旋转 generation / session / sequence 协议继续负责归属与请求有效性。权威目标旋转是玩家请求，实际物理姿态可以因碰撞尚未到达该目标，两者不能混作同一确认值。

## 物理拾取与碰撞

Pickup 改为服务器物理抓取：保持根物理组件模拟和场景碰撞，停止附着相机，只更新 Physics Handle 的目标位置与旋转。跟随响应按公共类参数和质量调整。

- 从目标当前真实位置开始抓取，不先传送到相机前。第一次拾取、滚轮拉近拉远和旋转均必须经过阻挡约束。
- 保持对场景静态和动态物体的碰撞；只排除持有者与目标之间会导致自碰撞推飞的物理接触，不能整体忽略所有 Pawn。
- 对目标路径做基于碰撞形状的 Sweep 和目标重叠检查，对大幅旋转分步检查，限制不合法目标；对适用刚体开启 CCD。不能依赖相机中心射线解决大物体边缘穿墙。
- 持续被墙阻挡时停留或滑动，不通过不断加大约束力量强制穿墙。距离失控、持有者传送或目标失效时服务器安全释放，禁止隔墙重新吸附。
- World 和 Pickup 的实际物理结果由服务器复制。客户端不独立权威模拟或强制写入无碰撞相机目标；平滑仅处理权威姿态，不破坏当前状态和释放位置。
- 放下使用物理组件真实变换。投掷沿用固定冲量，不额外手动除以质量。
- Equipped 保留现有插槽表现，Stored 保留隐藏、无碰撞和休眠。手持物理模式变化不能误改变装备/库存行为。

保留归属状态版本号、迟映射重试及晚加入处理。尚未映射的 Holder 不代表目标回到 World；物理抓取资源在 World、Stored、Equipped、销毁和功能清理时幂等释放。

## 总负重与角色属性

角色公开蓝图可读属性与仅服务器可写的修改入口：

- `MaxCarryWeightKg`：默认 200 kg，必须为有限正数，运行时改变会刷新负重结果并复制。
- `BodyWeightKg`：默认 80 kg，用于别人搬运自己；不加入自身负重。
- 当前总负重、负重比、运动倍率和是否超重：均可查询，真实值由服务器决定。

物品负重等于检查槽、装备槽和库存中有效且归属本角色的不同物品质量之和。按对象身份去重，并验证生命周期与槽位一致；禁止通过客户端库存数量或复制到客户端的 Actor 可见性推算重量。

搬运队友时额外加入队友身体重量及其仍实际拥有的物品重量。按照本阶段规则，布娃娃已掉出的世界物品不再计入队友或搬运者负重。禁止搬运链与循环，避免递归计重。

设总重量为 W、承重上限为 C，则：

`LoadRatio = Clamp(W / C, 0, 1)`

`MovementMultiplier = 1 - LoadRatio`

| 总重量（C = 200 kg） | 行走/跑步/蹲行速度倍率 | 跳跃初速度倍率 |
| --- | --- | --- |
| 0 kg | 1.0 | 1.0 |
| 100 kg | 0.5 | 0.5 |
| 150 kg | 0.25 | 0.25 |
| ≥ 200 kg | 0 | 0 |

倍率作用于角色基础 WalkSpeed、RunSpeed、CrouchSpeed 和初始化保存的基础 JumpZVelocity，不能对已经衰减的值再次相乘。跳跃初速度线性降低意味着固定重力下跳跃高度近似按倍率平方降低；本规格不宣称跳跃高度本身线性降低。

超重只禁止主动移动与新起跳，不关闭重力或将角色悬停。达到上限时清除主动水平移动，空中角色继续下落；布娃娃和外部物理仍按现有规则运行。超重限制与检查、落地、死亡锁分开，不能令超重角色无法交互卸重。

唯一运动参数刷新路径组合基础速度、跑步请求、负重倍率和已有锁定状态。负重改变、跑步切换、蹲行、落地解锁和布娃娃恢复均通过该路径，避免缓存旧速度使角色恢复满速。

负重由权威状态成功转换、销毁清理、质量变更和承重上限变更触发重算，不在每帧遍历全部库存。总负重和承重属性复制到拥有客户端以支持 CharacterMovement 的相同运动约束，必要的远端表现字段按实际消费者声明复制条件。服务器始终使用权威运动限制，不信任客户端倍率。

## 卸重与输入

保留普通物品 F 拾取、2 装备、V 入库、右键放下检查物、G 投掷装备物。

为保证仅库存导致的超重也可解除，G 在没有任何活跃目标时请求放下最后入库的有效物品。客户端只表达卸重意图，不提交库存下标、目标或释放变换；服务器选择最新库存条目并验证安全落点，成功后清理条目和重算负重。

搬运队友时 F 不会替换当前目标，右键或 G 安全放下；2 和 V 拒绝队友目标。搬运模式不进入检查光标和镜头锁定，玩家按负重规则正常移动与观察。普通检查态保留当前分支可移动输入，重量影响移动和跳跃。

## 布娃娃队友搬运

角色提供公共可搬运契约，仅在已确认的 Ragdoll 阶段开放目标，并返回 SkeletalMesh 及配置骨盆骨骼。搬运者必须存活、非布娃娃、没有检查物、装备物或被搬运目标，且与目标角色属于同一非中立阵营，目标不能是自己。

服务器重新检测骨骼命中、距离、遮挡、阶段、阵营、物理体和占用。扫描须覆盖布娃娃 Mesh 对象类型并保持墙体遮挡检查，不能沿用只扫描 thing 通道的物品射线。

请求采用当前同帧仲裁规则，目标权威记录唯一搬运者。拾取和恢复请求竞争时重新验证当前阶段和占用，仅一个合法转换生效。

取得目标后，以 Physics Handle 抓取目标骨盆刚体，不把 Character 根组件或整套骨骼刚性附着相机。目标保持服务器布娃娃模拟，其他骨骼自然下垂并与场景碰撞。已有布娃娃姿态采样和复制继续同步完整结果，不新增客户端第二套骨骼物理解算。

搬运者引用、目标引用和有效状态须可复制，晚加入能恢复搬运表现。被搬运角色在占用期间拒绝起身；放下解除占用但保持 Ragdoll，随后由原有速度、地面和站立胶囊空间检查决定能否恢复。

死亡角色若仍处于有效 Ragdoll 且 Actor 尚在场，可按同阵营规则搬运；死亡规则继续禁止复活或恢复。不能为了可搬运而自动改变死亡进入布娃娃的现有行为。

## 状态清理与失败处理

- 物品或布娃娃目标组件、骨骼、场景或必要依赖缺失：拒绝开始，原状态与负重保持不变，输出具体 LogECP 诊断。
- 搬运者布娃娃、死亡、失去控制权、断线、销毁或关卡结束：释放物理抓取，解除目标占用、持有者引用和负重贡献。
- 目标销毁、阶段变化、骨骼失效或退出场景：搬运者清除目标、释放 Handle 并刷新负重；相互清理幂等，不能重复扣重。
- 保留进入布娃娃时物品掉出规则；进入边沿与死亡同时发生不得重复掉落。搬运清理不能产生新的布娃娃进入事件或触发第二次爆出。
- 状态复制、物理移动复制、持有者引用映射和布娃娃快照不保证到达顺序；旧状态不能覆盖更新状态。BeginPlay 前收到状态也须正确恢复。
- 超重状态中卸重请求仍可执行。放置没有安全空间时保持持有并明确反馈，不能生成墙内物品。
- 功能退出与 EndPlay 清理定时器、委托、抓取和弱引用，避免跨 PIE 实例残留。

## 验证与验收

实施前为已有缺陷和边界建立能失败的自动化用例，再修改实现。验证依据实际结果报告，不将结构检查或单元测试描述为多人视觉验收。

### 规则和集成自动化

1. 空载、100、150、199、200、超过 200 kg；承重上限从 200 改为 300；非法输入不能产生 NaN 或负倍率。
2. 检查、装备、库存转换总重守恒；重复引用只计一次；入库后质量不变；丢弃、销毁、质量变更及时刷新。
3. 跑步、蹲行、落地和布娃娃恢复不会覆盖负重速度；零负重恢复基础参数；超重禁止起跳但仍可卸重。
4. 仅库存超重时 G 可卸重；释放失败不扣重；重复请求与晚到请求不错误丢弃其他物品。
5. 公共类与中型兼容类加载、原质量覆盖和能力默认值正确；已有小物品功能与旋转序号回归不退化。
6. 布娃娃仅同阵营可拾取，正常阶段、自身、忙碌持有者、占用目标、搬运链均拒绝；同帧竞争唯一胜者。
7. 队友身体重量计入搬运者且释放后移除；已掉落物品不计重；拾取、放下、恢复和销毁相互竞争时保持状态一致。
8. 各权威属性和引用声明正确，复制回调在乱序或暂未映射时不会重置正确物理状态。

### 物理与多人实测

- 小、中型实际蓝图在墙、门框和桌边拾取、滚轮移动、旋转与放下；快速拉动与首次拾取不能把物体直接传送穿墙。允许物理求解的微小接触误差，但不能持续穿墙或把物体拉到墙另一侧。
- Listen Server 加两个客户端：各端发起物品/队友拾取，旁观姿态一致，争抢唯一归属，断线正确释放，晚加入看见当前状态。
- Dedicated Server 加客户端：屏幕外布娃娃仍能抓取与采样，服务器物理正常，没有依赖本地控制器的抓取计算。
- 模拟延迟与丢包：持续移动、滚轮和旋转后最终状态一致，无旧请求覆盖新抓取、反复释放或永久锁定。
- 队友身体碰撞、拖过门框、搬运者倒地、目标死亡和放下后恢复；现有 crouch / jump / ragdoll temporal 回归继续通过。
- 编译 Editor 与 Game 目标，运行 ECP.Pickup、ECP.Ragdoll 及相关 Character 自动化。真实客户端视觉与网络实测未执行时明确保留为未验证项。

## 本阶段不扩展的范围

不引入 GAS、新背包 UI、跨局存档、装备系统重做、救援动画或复活玩法。不同角色的承重和身体重量允许配置，但不新增成长规则。除必要的新原生能力及兼容适配外，不重构其他 GameFeature 或批量迁移资源。
